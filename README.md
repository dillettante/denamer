# denamer

**한국어 문서 비실명화 도구 — 검은 박스로 "덮는" 것이 아니라 원문을 "삭제"합니다.**

판결문·서면·공문서·계약서 같은 문서에서 이름·주민등록번호·전화·계좌·카드·여권·주소·
법인명·사건번호를 탐지해 제거합니다. 모든 처리는 로컬에서만 이루어지며 네트워크 전송이
없습니다.

## 두 개의 빌드 — 목적이 정반대입니다

|  | **외부용** `denamer_out.py` | **내부용** `denamer_in.py` |
|---|---|---|
| 쓰는 곳 | 밖으로 내보내는 문서 (제출·배포) | 안에서 쓰는 문서 (LLM 질의) |
| 가역성 | **비가역** — 복원 불가 | **가역** — 매핑표로 복원 |
| 매핑표 | 없음 (가명화 대장은 선택) | 필수 |
| 선택 | 익명화(김OO) / 가명화(A·B·C) | 토큰(`[[PERSON_01]]`) / 가명(A·A사·사건A) |
| 입·출력 | PDF → PDF, DOCX → DOCX | PDF·DOCX·TXT → 텍스트 + 복원키 |

**내부용에는 익명화가 없습니다.** 김철수와 김민수가 모두 `김OO`이 되면 복원이 원리상
불가능하기 때문입니다. 내부용은 되돌아오는 표기만 제공합니다.

## 지원 형식

| 형식 | 외부용 | 비고 |
|---|---|---|
| PDF | ✅ | 좌표를 찾아 `apply_redactions`로 객체·픽셀 삭제. 스캔본은 OCR 자동 |
| DOCX | ✅ | OOXML 파트를 직접 수정. 번호류는 `■■■■`(고정 길이)로 가림 |
| XLSX·PPTX·구 .doc·HWP·MSG | ❌ | 막고 안내합니다 — PDF로 내보낸 뒤 처리하세요 |

DOCX는 **화면에 보이지 않는 자리**까지 훑습니다. 본문에서 사라진 것만 보고 안심하면
안 되는 곳들입니다.

    본문·표·텍스트박스 · 머리글/바닥글 · 각주/미주 · 주석(+작성자 이름)
    변경이력(삭제된 텍스트가 파일에 남아 있습니다) · 필드 코드
    하이퍼링크 대상(mailto:) · 문서 속성(작성자·최종수정자·회사·관리자)

Word가 한 단어를 여러 조각으로 나눠 저장하는 것(`김철` + `수`)까지 감안해, 단락 단위로
텍스트를 이어 붙여 찾고 원래 조각들에 도로 나눠 담습니다.

**가려지지 않는 것**: 그림 속 글자, 임베디드 개체(삽입된 엑셀 등). 해당 문서면 리포트
`warnings`에 표시되니 육안으로 확인하세요.

빌드를 나눈 이유는 안전입니다. 한 도구가 둘을 겸하면 **복원용 매핑표를 산출물과 함께
보내는 사고**가 언젠가 납니다. 외부용에는 복원 코드 자체가 없어 그 사고가 구조적으로
불가능합니다.

**탐지 규칙은 두 빌드가 공유합니다**(`detect.py`). 규칙을 두 벌 두면 한쪽만 고쳐 놓고
다른 쪽이 새기 때문입니다.

## 왜 "진짜 삭제"인가

PDF 위에 검은 사각형을 얹는 방식은 눈에만 안 보일 뿐, 원본 텍스트가 문서 안에 그대로
남습니다 — 복사·전체선택·OCR·LLM 투입 시 전부 노출됩니다. denamer는 PyMuPDF의
`apply_redactions()`로 해당 영역의 **텍스트 객체와 스캔 이미지 픽셀 자체를 삭제**한 뒤
그 자리에 표시(검은 박스 또는 대체어)를 그립니다. 저장된 PDF에서 원문 복원은 불가능합니다.

## 외부용 — 두 가지 모드

| | 익명화 `--mode anon` (기본) | 가명화 `--mode pseudo` |
|---|---|---|
| 이름 | 홍길동 → **홍OO** (성 보존) | 홍길동 → **C** (일관 치환) |
| 법인명 | 동방화학 → **A사** | 동방화학 → **A사** |
| 사건번호 | 2020가합12345 → **사건A** | 2020가합12345 → **사건A** |
| 주소 | 시·도만 보존, 나머지 O | 익명화와 동일 |
| 번호류 | 검은 박스 완전 삭제 | 익명화와 동일 |
| 대장 파일 | **남기지 않음** | `pseudonym_ledger.json` |
| 출력 | `원본명_masked.<확장자>` | `원본명_aliased.<확장자>` |

법인명·사건번호는 두 모드 모두 가명으로 바꿉니다. `○○화학`식 부분 가림은 읽기 어렵고,
같은 법인이 문서 안에서 같은 이름으로 불려야 문장이 성립하기 때문입니다. 다만 익명화
모드에서는 대장을 파일로 남기지 않습니다(문서 내 일관까지만).

가명화 대장은 문서 간 일관성을 유지합니다 — 같은 대장을 쓰는 한, 여러 문서에서 같은
사람은 항상 같은 가명을 받습니다. 대장에는 실명↔가명 매핑이 들어가므로 **산출물과 함께
배포하면 가명화가 무효**입니다. 반드시 로컬에만 보관하세요.

## 설치·사용

```bash
git clone https://github.com/dillettante/denamer.git && cd denamer
python3 -m venv --system-site-packages venv
./venv/bin/pip install pymupdf \
  "ko-pii @ git+https://github.com/Marker-Inc-Korea/ko-pii.git@635ade22cfe8d89761ed0e8948b5470e2307506e"
# 스캔 PDF 자동 OCR을 쓰려면: brew install ocrmypdf  (tesseract kor 포함)
```

### 외부용

```bash
./venv/bin/python denamer_out.py 문서.pdf                 # 익명화 → 문서_masked.pdf
./venv/bin/python denamer_out.py 문서.pdf --mode pseudo   # 가명화 → 문서_aliased.pdf
./venv/bin/python denamer_out.py 문서.pdf --skip ORG,CASE # 법인명·사건번호는 건드리지 않기
./venv/bin/python denamer_out.py 문서.pdf --names 인명사전.txt
./venv/bin/python denamer_out.py 문서.pdf --no-ocr        # 스캔본에도 OCR 안 함(경고 붙음)
./venv/bin/python denamer_out.py 의견서.docx              # DOCX → 의견서_masked.docx
```

### 내부용

```bash
./venv/bin/python denamer_in.py mask 문서.pdf                  # 토큰 표기(기본)
./venv/bin/python denamer_in.py mask 문서.pdf --style alias     # 가명 표기(A·A사·사건A)
#   → 문서_내부용.txt            (LLM에 붙여 넣을 것)
#   → 문서_복원키(원문포함).json  (외부 전달 금지)

./venv/bin/python denamer_in.py restore 답변.txt -k '문서_복원키(원문포함).json'
#   → 답변_복원.txt
```

토큰 표기는 원문과 충돌할 일이 없어 가장 안전합니다. 가명 표기는 사람과 LLM이 읽기
자연스럽지만 맨몸 문자열이라, 원문에 이미 `A`가 쓰였으면 자동으로 `A2`로 비켜 갑니다.

### 검사

```bash
./venv/bin/python test_denamer.py      # 회귀 테스트 256건
./check_web_parity.sh                  # 웹판이 코어와 같은 결과를 내는지 대조 (node 필요)
./check_no_private.sh                  # push 전 개인정보 흔적 검사
```

- 원본 파일은 절대 수정하지 않습니다.
- 스캔 PDF는 `ocrmypdf`(kor+eng)를 자동 실행한 뒤 처리합니다. 텍스트 레이어가 아예
  없을 때는 물론이고, **레이어가 있어도 쪽당 글자수가 적고 이미지가 쪽을 덮고 있으면**
  스캔본으로 보고 전 쪽을 다시 읽습니다(도장·머리글만 텍스트인 문서). 이 판단이 없으면
  그런 문서가 탐지 0건으로 통과합니다.
- `ko-pii` 미설치 시 정규식·규칙 탐지만으로 동작합니다.
- 종료 코드: 잔존·매핑실패가 있으면 **1** — 이때 출력물을 신뢰하지 마세요.

## 웹판 (`denamer.html`)

단일 HTML 파일 —
[**여기서 내려받아**](https://raw.githubusercontent.com/dillettante/denamer/main/denamer.html)
브라우저에서 열고 PDF를 끌어놓으면 끝. 설치 불요, 오프라인 동작, 파일은 어디로도
전송되지 않습니다. 외부용 계열이며(복원 없음), 페이지를 이미지로 재조립하므로 출력에
텍스트 레이어 자체가 없습니다(검색 불가, 대신 복원도 불가능).

웹판의 탐지 규칙·사전은 **파이썬 코어에서 생성**합니다(`python sync_web.py`).
사본을 손으로 옮기면 반드시 어긋나고, 데스크톱판만 고쳐진 채 웹판이 옛 규칙으로 남아
조용히 새는 것이 가장 흔한 사고이기 때문입니다. `check_web_parity.sh`가 두 구현이 같은
결과를 내는지 실측으로 확인합니다. ko-pii는 웹판에 없습니다.

## 탐지 방식

1. **정규식 엔진** (24종) — 주민·외국인등록번호(자간·유니코드 대시·무하이픈 허용, 생년월일
   타당성 검증), 카드(Luhn), 여권, 사업자등록번호(체크섬), 법인등록번호, 운전면허,
   계좌(문맥어 기반), 전화(국번 화이트리스트), 이메일, 차량번호, 사건번호(법원·검찰·
   노동위·조세심판·행정심판·위원회), 법인명, 주소.
2. **이름 엔진** — 라벨 174종(당사자 81 · 친족 관계어 43 · 직함·호칭 등), 괄호 식별자,
   서술어 결합, 여격 조사, 자간 라벨(`참    조서민수님`), 이미 부분 마스킹된 표기(김○○).
   성씨 게이트와 비이름 사전 752단어로 오탐을 억제합니다.
3. **ko-pii** (형태소 기반, 데스크톱판) — 라벨 없는 자유문장 속 이름·주소.
4. **제거** — 탐지된 값 문자열을 페이지 전수 검색(리터럴 + 자간 변형 워드 폴백)해 모든
   출현을 삭제. 오프셋→좌표 역매핑을 쓰지 않으므로 그 계열의 좌표 어긋남 버그가
   구조적으로 불가능합니다. 조사가 함께 지워지면 대체어 뒤에 다시 그립니다(`김OO에게`).
5. **사후검증** — 저장본을 다시 열어 재검색. 잔존 발견 시 시끄럽게 실패(exit 1).
   메타데이터·XMP도 소거하고 잔존을 확인합니다.

## 한계 — 반드시 읽으세요

- **자동 탐지는 완전하지 않습니다.** 규칙·사전 기반이므로 서식·인코딩·OCR 품질에 따라
  놓치는 값이 있습니다. 한글로 음차한 외국인명(스미스 등)은 성씨 게이트 구조상 자동
  탐지에서 빠집니다 — `--names` 사용자 사전으로 보완하세요.
- **OCR 경유 문서는 OCR이 읽어낸 글자에만 적용됩니다.** OCR이 놓친 글자는 스캔 이미지에
  그대로 남고, 사후검증은 그것을 알지 못합니다. 추출량이 적으면 리포트가 경고합니다.
- 사후검증은 "탐지한 값"만 재확인합니다. 탐지 자체가 놓친 값은 검증도 모릅니다.
- **외부 제출 전, 결과물을 원본과 대조하는 육안 검토가 이 도구 사용의 전제입니다.**

## 파일 구조

```
detect.py            탐지 규칙 + 검증기 + ko-pii 통합   ← 두 빌드가 공유
names.py             이름 문맥 규칙
stopwords.py         비이름 사전 (752단어)
ledger.py            가명 대장 (유형별: 사람·법인·사건)
docx_io.py           DOCX 파트 읽기·치환·검증 (숨은 자리 포함)
denamer_out.py       외부용 — PDF·DOCX 비가역 비실명화
denamer_in.py        내부용 — 텍스트 마스킹·복원
denamer.html         웹판 (외부용 계열, 단일 파일)
sync_web.py          웹판 규칙 생성기
test_denamer.py      회귀 테스트
check_web_parity.sh  웹판↔코어 대조
check_no_private.sh  공개 저장소 개인정보 검사
```
